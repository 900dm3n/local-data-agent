# 架构与关键设计

## 一次分析的链路

用户问题 → 发现 Schema 与批准口径 → 检索业务文档和工单原文 → 模型提交计划 → 本地执行工具 → 根据反馈补查或修订 → 核对源事件与结果 → 发布报告。

原生框架由 LangChain `create_agent` 驱动。模型通过 `StructuredTool` 选择受控工具；中间件维护请求预算、上下文副本、工具调用 ID 和终止条件。业务计算与发布校验在普通 Python 模块中实现。

## 计划与执行

MiniPlan 使用命名步骤与依赖 DAG。增量补丁先校验完整依赖图，再使受影响的下游结果失效；未变分支复用原产物。SQLite 查询只针对注册表，DuckDB 执行后续聚合，产物保存为带 Schema、行数和哈希的 Parquet。

只读 SQL AST 检查、关闭外部读写、子进程超时与行数限制共同限定执行范围。这些是应用约束，不能承诺抵御所有操作系统级攻击。

## 检索与上下文

文档按确定性规则分块，保留原始文本偏移。FTS5 与元数据条件检索业务定义、字段和值，工单引用绑定原文位置。模型默认只看到有界预览，完整轨迹另行归档。上下文副本保留工具请求与回复配对，不把永久轨迹改写成模型摘要。

## 状态与恢复

业务账本、LangGraph 检查点与工作台任务分别使用 SQLite。恢复先取得运行锁并检查冻结输入与产物，再同步具有稳定 ID 的消息。已提交的同一工具调用可复用输出；已发送但响应未归档的模型请求仍可能在恢复时重复，不能承诺 exactly-once。

## 核验与报告

示例口径由独立源事件账本核对，金额、差额和趋势说明从实际结果表生成。报告记录产物引用、筛选范围和计算方式。程序核对金额、需求覆盖、文本解释与因果推断属于不同层次的评价。

## 公开版本

仅发布应用源码、测试、可复现的合成数据生成器与无密钥配置。私人模型调用、历史结果、密钥文件、个人环境路径和原始开发委派记录均不发布。原生框架入口是 `python -m langchain_data_agent`；业务核心包中的旧入口用于兼容测试。
